# Close Day v3

End-of-day Area Manager Shift Report and session close-out for the post-vault-cutover BTQ workflow.

## Purpose

Create Jordan's daily shift report and session file from today's processed operational activity, outbox items, Grimoire journal notes, and rollover context. The markdown vault is frozen for entity data after cutover; read entity activity from CouchDB through `btq export-vault-today`.

## Step 1 - Read source material

Always read:

- Run `btq export-vault-today --date YYYY-MM-DD` (from the btq project directory).
  This outputs today's entity activity from btq_vault: visits, new hires, issues,
  supply needs, equipment requests, and personnel events. If the command is
  unavailable or returns an error, skip this source and note it.
- `BTpipeline/outbox/`
- `Grimoire/Journal/YYYY-MM-DD.md`
- Most recent prior shift report for rollover: glob both `Grimoire/Shift Reports/*-shift-report.md`
  for post-cutover reports and `B&T/Journal/*-shift-report.md` for pre-cutover
  reports; use the newest report across both locations.

Read-only inputs are evidence. Do not mutate source files while collecting context.

## Step 2 - Draft the shift report

Use the Area Manager Shift Report format. Keep the report practical and operational: what happened, what changed, what needs follow-up, what is blocked, and what should roll into tomorrow.

Preserve these field definitions:

- Date: the report date in `YYYY-MM-DD`.
- Manager: Jordan.
- Entity Activity: visits, new employees, site issues, supply needs, equipment requests, and personnel events from `btq export-vault-today`.
- SafetyCulture / Outbox Items: inspection, audit, or external form items waiting in `BTpipeline/outbox/`.
- Grimoire Journal: human notes and context from `Grimoire/Journal/YYYY-MM-DD.md`.
- Follow-ups / Rollover: unfinished items from the newest prior shift report, unless today's evidence shows they are complete or obsolete.
- Risks / Blockers: items that can delay service, staffing, supplies, client communication, or billing.
- Tomorrow: the smallest concrete set of next actions.

Rollover principle: do not blindly copy prior tasks. Carry forward only work that still has an operational reason to exist, and rewrite it as a current next action.

SafetyCulture field mappings:

- Treat SafetyCulture inspection titles as the primary item label.
- Treat site, account, location, or client fields as site context.
- Treat failed, flagged, or action-required responses as follow-up candidates.
- Treat photos, notes, and corrective actions as supporting evidence.
- If a SafetyCulture item lacks enough context to assign a site or next action, include it under review-needed rather than inventing details.

## Open Positions — derived, not rolled

Do **not** carry forward the prior shift report's Open Positions list.
Instead, run `btq open-positions` from the btq project directory:

```bash
btq open-positions
```

The output is markdown-ready and reflects the current vault state of
recruiting efforts: every site whose `### Recruiting Triggers`
entries outnumber the matching `### Recruiting Closed` entries with
outcome `filled`, `cancelled`, or `superseded`.

`withdrawn` does NOT close a position — a withdrawn recruiting
effort means the recruiting was withdrawn but the underlying need
may persist. Use the rollover mechanism only for items not yet
captured by the queue (e.g. coverage gaps Jordan knows about but has
not staged a `trigger_recruiting` for yet) — and stage those
trigger_recruiting jobs in the same closeday session so the next
report's list is fully queue-derived.

If `btq open-positions` is unavailable or errors, fall back to the
prior-report rollover and note the fallback in the report.

## Step 3 - Write the shift report

Save the shift report to:

`Grimoire/Shift Reports/YYYY-MM-DD-shift-report.md`

Use this template:

```markdown
# Area Manager Shift Report - YYYY-MM-DD

## Summary

## Entity Activity

## SafetyCulture / Outbox Items

## Journal Notes

## Follow-ups / Rollover

## Risks / Blockers

## Tomorrow
```

## Step 4 - Write the session file

Write the session file to:

`Grimoire/Sessions/YYYY-MM-DD.md`

Record what was reviewed, what was written, any skipped sources, and where the shift report was saved.

## Step 5 - Confirm to Jordan

Confirm:

- The shift report path: `Grimoire/Shift Reports/YYYY-MM-DD-shift-report.md`
- The session file path: `Grimoire/Sessions/YYYY-MM-DD.md`
- Any skipped or unavailable source, including `btq export-vault-today`
- Any high-priority rollover items that need Jordan's attention tomorrow

Do not claim source coverage that was not actually read.
